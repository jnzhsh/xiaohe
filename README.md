# 小禾 Android

温暖的个人生活与学习助理，Android 8.0 及以上。单一聊天入口，不要求先选择分类。

## 1.6.0 已有记忆问答

查询先找本机已经记录的资料，再让模型作答。短追问沿用首次发送时固定的近期引用；“他们”等复数话题可以找到相关的多个人，不只沿用最后一个人。当前明确指定的名字、身份或新话题优先。归档资料仍可作依据，旧菜谱等笔记不会因为“上次”而被一律排除；未知日期照实说明。

问答使用独立的只读流程。普通问题、背景加问题、没有问号的“多少／多久”，均不会新增生活记忆、待整理条目或提醒。模型没有采用已知资料、给了无效依据或接口失败时，先展示本机可核对的内容；原问题可重试，时间锚和上下文保持不变。明确要求记住、修改、提醒等输入继续使用写入流程。

一次问答至多发送 30 条候选资料，候选投影受 60000 字符预算限制，长文包含相关片段并标注截取；不保证完整覆盖全部记录。引用逐条核对实际发送的 ID 和当前内容，区分当前、历史、不同说法、计划与已发生内容，不把参考建议当作用户已有事实。

本机仅保存本次候选 ID、版本、覆盖说明、原时锚及请求摘要哈希，便于后续排查；不保存原始模型请求体、密钥或接口头。老版本未保存的请求无法从备份还原。方案、基线和实际验证维护在 [Issue #9](https://github.com/jnzhsh/xiaohe/issues/9)。

## 1.5 聊天修改记忆

在记忆或事项详情点“补充或更正”，原记录会作为卡片附到输入区。直接说“改到明天下午四点”“同行人换成某某”或“补充一句”，发送后由 AI 提出修改，手机核对选中的编号、版本和原话再保存。完成、归档、放回手边与设置提醒也走同一入口，按钮只准备可编辑的话，点击时不会改动记录。

附上的记录不受初始聊天检索窗口限制；同名条目按编号区分。单纯询问不会修改，询问或连接失败后，输入区没有新草稿时会保留这条关联供继续说。发送成功的修改会清除关联。原记录已变化时，需要明确重新选择当前版本，应用不会自动覆盖新内容；网络或模型结果不合要求时，原记录保持，修改原话可重试。

“明天”按这次修改输入的原始时间与时区固定；语音沿用该草稿的首次录音时间。只改日期保留原来明确的钟点，只改钟点保留原日期，已有提醒随改期移动。未明确早晚的时刻不会猜测，完成或归档会停用提醒。以前手动更正后暂停的事项不继承不可信的旧时刻，完整新时间与当前文字、对象核对后才恢复为可查询安排。

正文以局部替换或追加更新，完整长资料尾部、原话和历史版本保留。事实值的更正或变化复用已有历史规则；身份或不同说法尚未明确时，会保留原记录并说明原因。备份继续使用 v2，新增聊天关联随对话导出，无需手工搬迁旧数据。实际行为仍取决于连接模型能否提出可核对的修改。任务与验证入口为 [Issue #11](https://github.com/jnzhsh/xiaohe/issues/11)。

## 1.4.0 GitHub 反馈

每条助手回复下的“反馈”以及设置中的一般反馈入口，可以在手机里填写问题、查看完整预览，再直接创建 `jnzhsh/xiaohe` 的 GitHub Issue。对话原文默认不附上，勾选后只附选中的回复及它对应的用户原话；不收集整份备份、其他对话、图片、录音、原件路径、接口地址或设备唯一编号。可选的版本与模型信息也会在预览中显示。

在应用的连接设置中填写 GitHub 令牌，令牌使用 Android Keystore 和 AES-GCM 加密，独立于主 AI 接口密钥，不进入备份，也不交给 AI。建议创建 fine-grained personal access token，仅选择 `jnzhsh/xiaohe` 仓库并授予 `Issues: Read and write`。[GitHub 创建 Issue 的权限说明](https://docs.github.com/en/rest/issues/issues#create-an-issue)。

先检查预览，再点创建 Issue 才发送。草稿与提交状态保存在本机；成功后显示真实编号和链接。断网、权限或限流失败保留草稿。网络中断等无法确认是否已经创建的情况会标为待核对，先检查 GitHub 结果，不自动重复发送。公开仓库的反馈可被他人查看，请以预览中的内容为准。

当前版本只核对最近 500 条 Issue；提交结果不明确且一直找不到对应回执时，会保留原草稿并暂停重发和新建反馈，暂不提供解除该状态的入口。

反馈是独立的 JS/CSS 与原生模块，不改变生活记忆数据库或备份格式。方案、当前源码版本与验证维护在 [Issue #8](https://github.com/jnzhsh/xiaohe/issues/8)；AI 回答调查另在 [Issue #9](https://github.com/jnzhsh/xiaohe/issues/9)，本功能不声称已经修复其中的 AI 行为问题。

## 1.2.2 键盘与输入

输入法弹出时，聊天输入区随可见区域上移，输入框与发送按钮保持可操作。可见区域较短时收起底部导航，键盘收起后恢复。设置弹窗中正在输入的字段会滚动到可见区域。

Android 11 及以上显式处理键盘与系统栏边距，实际调整 WebView 尺寸；Android 8–10 保留系统窗口缩放。记录与素材格式沿用 1.2.1，安装包继续使用原签名，可以覆盖安装。

本次修复的基线、人类授权、复现和验证证据维护在 [Issue #1](https://github.com/jnzhsh/xiaohe/issues/1)。

## 1.2.1 日期与粘贴

用户输入中的“今天、明天、后天”等可确定日期，在首次保存时按该条输入的时间与时区固定为绝对日期。记忆卡片和详情显示明确的年月日，原话保留在来源中。重试与备份恢复沿用原锚；未知作者时间的附件或链接不会套用导入日期。日期已知但“8点”早晚未明时，保留日期与“时刻未定”，不自动猜测或安排提醒。

“我明天有什么安排”等个人日程概览按提问当天的时区计算日历区间，从全量本机数据库查询有效安排，不依赖记录正文是否含“明天”。问句不新增日程，未定日期的事项不冒充当天安排，已完成、取消或旧说法会排除。这类查询不依赖模型连接。

连接设置与聊天输入提供“粘贴”按钮。粘贴前结束输入法组合，通过编辑器插入文字并保留后续输入状态。手机读取本机剪贴板；此工作区的模拟器体验版由粘贴助手在用户点击或按 Ctrl+V 时读取电脑剪贴板。剪贴板文字不写入助手日志或命令参数。

记录、对话、附件和归档保存在手机的应用私有目录；模型请求直接发到用户配置的接口，没有中间业务服务器、账号系统或云同步。API 密钥使用 Android Keystore 和 AES-GCM 加密保存在本机。

## 第一次使用

安装 APK，打开右上角设置，填写兼容 OpenAI Chat Completions 格式的接口基础地址、模型名称和 API 密钥，再点“试着连接”。基础地址可以是 `https://服务域名/v1`，也可填写完整的 `/chat/completions` 地址；局域网与本机 HTTP 接口可用。

主模型默认只处理文字。“这个模型能看图片”默认关闭。开启后，当次图片抽样会发到该模型接口。截图文字使用安装包内的中英文 Tesseract OCR 在本机提取，不依赖网络下载。

聊天里的“语音”使用内置 sherpa-onnx 与中文 Zipformer14M 模型，在手机上录音并转成文字，不依赖系统中文识别服务，也不用配置转写接口。停止后文字回填草稿，校对后自行发送；录音原件留在本机，识别失败没有上传音频的自动回退。第一次语音的时间与时区跟随当前草稿，追加、编辑与重试保留这个基准，发送或清空草稿后重置。

从其他 App 导入的音频素材、视频声音仍使用独立的 OpenAI-compatible `/audio/transcriptions` 转写接口；这部分未连接服务时保留原件并标注未转写。与主模型同一服务（协议、主机和端口一致）时可以复用密钥，也可单独填写转写服务和密钥。

## 输入和查找

直接说、粘贴链接、选择附件，或从其他 App 分享文字、链接、截图、视频到“小禾”。内容先在本机保存，再识别和整理。AI 暂时连不上时，原始输入不会丢失，可以稍后重试。

可以把多件事放在同一条消息里。分类由模型生成，可新增，不限于生活或学习。模型会把长期事实、个人偏好、待办与日程分开保存。查询包含已归档的记录；也可在记忆页面按文字、分类或状态查找。

记忆页将主题与细标签分开浏览：主区域最多显示五个主题，其余从“更多主题”搜索；人物、品牌、物品等线索保留在默认收起的“按标签找一找”。卡片只展开三个标签，详情仍可查看全部。主题与标签数量按全量本机库的当前状态和搜索范围计算，分页不会漏掉后面的记录。

已有标签、原话与历史不改写。主题是查询时从现有标签索引的写入顺序派生的显示分组，不是新的事实字段；应用写索引时沿用原标签数组顺序。应用没有 VACUUM 路径，外部重建索引如果改变顺序，需要按原数组重新索引。新记录提示模型把可复用的主题放在首位，再补少量具体线索；自由输入保持不变。旧 `tag` 查询仍匹配任意标签，新增 `theme` 只筛首个有效标签。方案及验收维护在 [Issue #3](https://github.com/jnzhsh/xiaohe/issues/3)。

旧手机同签名覆盖升级后直接使用这个显示分组，无需为分类导出再导入；换手机仍沿用原备份导入流程。旧标签的首项如果是具体词，该词仍显示为主题，不会被重新交给 AI 做语义分类或自动合并同义词。主题浏览、筛选事件和样式由 `memory-browser.js/css` 负责，主界面只负责接入，避免与语音会话的状态和样式一起修改。

## 归档与提醒

每周由 Android JobScheduler 检查一次：已完成满 7 天、且未标记长期保存的资料或临时事项进入归档。未读、未完成、尚待解析、待确认和长期记忆保留。归档可以恢复，原始素材继续保留。

具体执行时间受 Android 的后台调度和手机厂商的省电设置影响。应用打开时也会检查是否到达整理周期。

记录详情中的提醒入口会把这条记录附到聊天，说明时间并发送后设置提醒。Android 13 以上需要允许通知；需要准时提醒时，Android 12 以上还需在系统设置允许准时闹钟。设备重启后会重新安排已有提醒。

## 导入导出

设置中“导出备份”会创建 `.xiaohe.zip`，包含全部对话、记忆、对象、分歧、历史版本、原始附件和校验信息。备份没有 API 密钥；非敏感接口配置只作为备份信息，不覆盖当前连接设置。

导入时先检查结构、路径、引用和附件 SHA-256，再在数据库事务中合并。相同编号不会重复，已有记录不会被覆盖；编号相同但文件不同的备份会被拒绝。可以在新手机安装后导入同一个备份，再重新填写密钥。

卸载应用会删除应用私有数据，卸载前请先导出。备份文件是普通 ZIP，可保存到你选定的位置。

## 素材识别的范围

- 图片：在本机做中英文 OCR；纯画面理解需要用户配置能看图的模型。
- PDF：本次渲染并识别前 5 页，完整文件保留，详情会说明覆盖范围。
- 视频：抽样 7 个画面；声音由独立转写接口处理。完整视频保留。
- TXT、Markdown、CSV、JSON 等：本机读取前 2 MB，完整文件保留。
- DOCX、PPTX、XLSX：本机提取文字，嵌入图片与排版不属于文字提取范围。
- 麦克风语音：内置轻量普通话模型，文字需要校对；噪声、方言、专有名词可能降低准确率。
- 导入音频转写：当前独立接口单次上传上限为 25 MB；更长音频可以分段导入。
- 需要登录、禁止读取或主要由网页脚本生成的链接，可能无法解析，会保留原链接并标明状态。

识别不是原件的替代品。无法识别的部分会保留原件和说明，模型不会被要求猜测缺少的内容。

## 编译

用 Android Studio 打开此目录即可使用标准 Gradle 工程。项目使用 AGP 8.9.2、Android SDK 35，Gradle 至少 8.11.1，JDK 至少 17；没有业务服务器依赖。

构建机需要 Python 3.11 以上。`prepare-asr.py` 下载 `asr-dependencies.json` 固定的 AAR、Kotlin 运行库与模型，校验 SHA-256 后提取到忽略提交的 `build/`。首次构建需要联网；已准备三个文件的机器可用 `python prepare-asr.py --cache <缓存目录>`。Gradle 的预构建任务也会准备这些依赖，可用 `XIAOHE_PYTHON` 指定 Python。安装后的应用不运行下载脚本、不下载语音模型。

`build-android.ps1` 是当前工作区的直接编译脚本，使用 SDK 的 aapt2、d8、zipalign 和 apksigner。签名私钥留在构建工作区，不包含在源代码包中。后续同一安装的升级包必须继续使用同一签名密钥。

独立 worktree 可通过 `-ToolsRoot` 指定现有构建工具目录，通过 `-OutputRoot` 指定制品输出目录，`-AsrCache` 使用已有语音依赖缓存；版本与 APK 文件名从 Manifest 读取。键盘回归的入口是 `verification/build-keyboard-tests.ps1`，需传入同一工具目录和应用的 `classes.jar`；测试设备限定为隔离的 `emulator-5556`。

## 1.1 记忆与版本

原消息记录 capturedAt/capturedZone/contextMessageIds，确定性日期解析与指代使用原时上下文。
对象有稳定编号；同名不同身份分开，无法唯一确定的对象和时间进入待确认。
事实状态与完成/归档状态独立；更正撤回错误说法，变化保留历史有效区间，缺少证据则保留分歧。
人工改动和恢复都会追加版本；涉及事实/事件结构时暂停旧自动提醒，避免文字已改而日程仍沿用旧值。

本机FTS4使用编码字符对和英语词，保留小数/分数/代码标点；精确重复合并来源，语义近似仍交给模型和用户确认。
記忆/人物/待办/历史分页，超出初始窗口的依据、对象与分歧按需读取。
Store.jsonRows/eachJson通过受限前缀与分次substr读回完整JSON，避免默认CursorWindow对大行的限制。
Backup v2按记录流式导出与导入，兼容v1；元数据64MB/总展开8GB/200000条上限在导出前也检查。

## 1.2 少打扰体验

MemoryCare 将信息含糊与用户现在是否需要补充、是否可安全自动提醒分别判断。
普通未定计划为 unscheduled，未定/低风险分歧留在后台，没有确认数量债务。
同名人物可沿用最近唯一明确上下文，日期假设保留原始锚、assumed/basis，资料原作日期仍不猜。
明确提醒缺实际安排条件时，只留下一个可验证的问题；补时刻支持前一轮唯一未延后目标，保留原日期和两轮原话。
选择以后再说持久延后同来源提醒；新普通时刻不追排旧提醒。MainActivity 在 Scheduler.schedule 返回真实结果后才确认实际安排。
数据库升级到3只重派生care/index与未知计划时间；既有手工内容和全部历史快照保留。
源包 verification 中保留本轮原生与界面场景。模型接口仍需用户配置，语义能力取决于实际服务。
